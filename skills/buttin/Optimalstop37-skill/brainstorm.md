# 时间窗口怎么定 · 什么场景适用

## 一、适合这套流程的议题

共同特征：**没有唯一正确答案，需要在多个"都不错"的方案里选一个，
而且想得越久越容易陷入反复。**

| 适合                | 不适合                                         |
| ------------------- | ---------------------------------------------- |
| 产品/页面改版方案   | 有标准答案的事实问题（"这个 API 怎么用"）      |
| 起名、Slogan、文案  | 纯执行任务（"帮我把这段重写一遍"）             |
| 活动/团建/旅行方案  | 情绪性倾诉（用户只是想被听见）                 |
| 技术架构的几种路线  | 唯一可行解（没得选就别走流程）                 |
| 内容选题、课程大纲  | 需要大量外部调研才能判断的事（先调研再定窗口） |
| 职业/合作机会的比较 | 已经拍板的事（别用流程给既成决定找补）         |

**判断标准**：如果这件事"再想 10 分钟"确实可能想出更好的，就适合；
如果再想 10 小时也不会更好，直接做。

## 二、窗口长度建议

| 议题类型                | 建议窗口 |
| ----------------------- | -------- |
| 起名、文案、短决策      | 2分钟    |
| 产品方案、内容选题      | 5分钟    |
| 架构选型、活动方案      | 15分钟   |
| 重大选择（offer、合作） | 30分钟   |

### 定窗口时的三个提醒

1. **宁短勿长。** 窗口太长，观察期会被无限拉长，最后变成没有约束的讨论。
   用户说"给我一天"时，可以追问："一小时够吗？多数情况下够。"
2. **窗口要能切进日程。** "三天"如果意味着三个零碎的十分钟，实际有效时间很短——
   按**有效投入时间**估算，而不是自然时间。
3. **先定窗口再发散。** 反过来（先聊起来再说）会让窗口形同虚设。

## 三、为什么必须等到 37% 才能选

经典秘书问题的结论：候选以随机顺序出现、不可回头时，
跳过前 **1/e ≈ 36.8%** 只观察不选，之后选第一个超过观察期最优的，
选到全场最优的概率约为 **37%** —— 这是此类问题的理论上限。

在头脑风暴场景里，对应含义是：

- **前 37% 是校准期**：你在这段时间建立"什么叫好"的标准（预定版本就是这个标准的载体）；
- **后 63% 是收割期**：带着标准去找更好的，找到一个就该停手；
- **37% 不是保证选对**：仍有约 63% 的可能错过最好的那个。
  它的价值是**给你一个能停止的正当理由**——多数人的实际失败不是"选错"，是"永远不选"。

> 观察比例可用 `--ratio` 调整：目标只是"足够好"而非"最好"时可降到 0.25-0.30，
> 更早开始接受，避免两头空。（除 37% 外的数值是经验值，不是精确解。）

## 四、出现这些信号时应放弃流程

| 信号                         | 说明                   | 该做什么                       |
| ---------------------------- | ---------------------- | ------------------------------ |
| 用户说"我心里其实有答案了"   | 他要的是确认和承担     | 直接问"你倾向哪个、怕的是什么" |
| 某个维度压倒性重要           | 决策已退化成单维度比较 | 直接按那个维度挑最优           |
| 用户一直在发散，从不 reserve | 在回避"停下来做决定"   | 推`due` 收口，别陪他继续发散 |
| 议题本身还没想清楚           | 版本之间没有实质差异   | 先花时间澄清问题，再开窗口     |
| 需要的信息根本不在对话里     | 缺外部事实             | 先去查/问，再走流程            |
